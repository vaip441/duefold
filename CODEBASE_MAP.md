# Duefold codebase map

Use this map before broad repository searches. It identifies ownership and useful starting points, not every file. Follow the nearest module map for detail.

Keep this map current in the same change that adds, removes, moves, or materially changes a capability owner, public entry point, route family, generated source, or primary test location. Ordinary internal refactors that do not change how someone finds a capability do not require a map edit. Validate links with `npx vitest run --project unit test/unit/codebase-map.test.ts`.

## System shape

Runtime composition is declared by modules and generated at build time. PostgreSQL functions in module migrations are authoritative for authorization and transactional audit; server routes adapt HTTP to those functions. The browser parses server decisions and never replaces server authorization.

- [Web server](apps/web/) — HTTP lifecycle, authentication hooks, route authority, static client, and composed route registration.
- [Web client](apps/web-client/) — member workspace, viewer reading room, browser API parsing, and shared interface components.
- [Worker](apps/worker/) — isolated and scheduled job execution.
- [CLI](apps/cli/) — database migration and operational commands.
- [Composition](packages/composition/) — manifests, declaration contracts, generated registries, and omission checks.
- [Shared](packages/shared/) — small cross-module primitives without product capability ownership.
- [Generated registries](.duefold/generated/) — generated by `npm run compose`; never edit directly.

## Common request paths

### Member administration

[Module declaration](modules/core-security/src/declaration.ts) → [member routes](modules/core-security/src/routes/) → [member reads](modules/core-security/src/member-reads.ts) or [member mutations](modules/core-security/src/member-mutations.ts) → [core-security migrations](modules/core-security/migrations/) → [browser parser](apps/web-client/src/api/administration.ts) → [focused administration hooks](apps/web-client/src/workspace/) → [member components](apps/web-client/src/components/).

### Room and document work

[Module declaration](modules/rooms-documents/src/declaration.ts) → [room/document routes](modules/rooms-documents/src/routes/) → capability source under [rooms-documents](modules/rooms-documents/src/) → [room/document migrations](modules/rooms-documents/migrations/) → browser API under [web-client API](apps/web-client/src/api/) → [room state](apps/web-client/src/workspace/) → [room view](apps/web-client/src/workspace/views/RoomView.tsx).

### Viewer access

[Participant grant functions](modules/participants-access/migrations/) and [viewer authorization](modules/rooms-documents/src/viewer-authorization.ts) → [viewer routes](modules/rooms-documents/src/routes/) → [viewer API](apps/web-client/src/api/viewer.ts) → [reading room](apps/web-client/src/routes/ViewerReadingRoom.tsx).

## Where tests belong

- Colocated `*.unit.test.ts` or `*.unit.test.tsx` — pure behavior, parsing, and components without external services.
- [Unit boundary tests](test/unit/) — repository-wide static contracts.
- [Authorization tests](test/authz/) — PostgreSQL authorization, transactional audit, concurrency, and protected route matrices; require `DUEFOLD_TEST_DATABASE_URL`.
- [Integration tests](test/integration/) — database-backed workflows and external-service doubles; require `DUEFOLD_TEST_DATABASE_URL`.
- [Browser tests](test/browser/) — user journeys, focus, responsive behavior, and accessibility.
- `npm run compose:verify` and `npm run compose:verify:minimal` — generated composition and omitted-module evidence.
